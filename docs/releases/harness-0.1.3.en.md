# mindie-harness 0.1.3: Great Subtraction, Zero-Git Wheelhouse Substrate & local-only Cold Stop

[中文](harness-0.1.3.md)

`mindie-harness v0.1.3` is a patch release of the zero-heavy-dependency, pure-Python-stdlib shared substrate (`mindie_harness`) powering all 7 MindIE Agent native host plugins (`codex`, `cc`, `kimi`, `dsh`, `agy`, `wb`, `oc`). It keeps `API_VERSION = 1` stable while tightening the diagnostics entrypoint, native read-tool classification, and native wait deadlines:

- **`mindie_doctor` Read Lane & Graceful Downgrade (`mindie_harness.mcp.router` / `mindie_harness.api`)**: Registers `mindie_doctor` in the default tool catalog (`readOnlyHint=True`, optional `cwd: str` and `probe_remote: bool = False`). Every call runs on the lock-free read pool without consuming `MAX_CONCURRENT_MUTATIONS_PER_SESSION` or writing mutation rows to `remote-receipts.sqlite3`. Dispatch prefers the lazy `mindie_diagnostics.doctor.run_doctor` entrypoint, falls back to a bounded `mindie-diagnostics doctor` child process, and returns a structured `doctor_unavailable` result when an older rollback generation lacks `doctor`, never breaking the MCP router.
- **Full 7-Host Native Read/Poll/Control Coverage**: `READONLY_TOOL_PREFIXES` now includes case-accurate `remote_Read`, `remote_Glob`, `remote_Grep`, `remote_TaskOutput`, `remote_TaskList`, `remote_TaskStop`, `remote_ViewImage`, `remote_ReadMediaFile`, `remote_view_image`, `remote_probe`, `remote_read_file`, `remote_find_by_name`, `remote_grep_search`, `remote_list_dir`, `remote_manage_task`, and related native names. `remote_Write`, `remote_Edit`, `remote_write_file`, `remote_edit_file`, `remote_run_command`, and `remote_Bash` remain classified as mutations. `remote_auth` stays out of the static prefix list: only `action == "status"` uses the read lane, while `setup` / `forget` retain mutation receipts.
- **Native Wait Tables & Doctor Budgets (`compute_tool_deadline`)**: `REMOTE_NATIVE_MAX_WAIT_MS` adds `remote_Bash` and `remote_TaskOutput` at `600_000ms` long-poll ceilings, and the `remote` surface now recognizes `yield_time_ms`, `timeout_ms`, Antigravity `WaitMsBeforeAsync`, and Claude/WB `timeout` (all milliseconds). `mindie_doctor` uses a `10s` local / `15s` probe inner budget plus cleanup grace, preserving `outer >= inner + grace`.
- **Version & Seed Synchronization**: `pyproject.toml`, `mindie_harness.__version__`, the public facade, bilingual READMEs, the release workflow, and `dist/mindie-harness-seed.pyz` / `dist/seed-lock.json` (`mindie-harness-seed/1`) all advance to `0.1.3` (`API_VERSION = 1`).
- **Zero-Git Prebuilt Wheelhouse Updater (`mindie_harness.runtime.wheelhouse` / `wheelhouse_assets`)**: Adds `discover_channel`, `stage_wheelhouse`, and `update_runtime` to read `release-channel.json`, `mindie-wheels-bundle.tar.gz`, and `SHA256SUMS` from GitHub Releases or a `file://` / local mirror, verify every asset with streaming `64 KiB` SHA-256, and promote it atomically. When the bundle is absent it falls back per component to `<repo>/releases/download/v<version>/*-py3-none-any.whl` with zero `git` or `git+https://` usage. A `6h` channel cache and bounded `1h -> 2h -> 4h -> 6h` exponential backoff live in `channel-cache.json` / `update-backoff.json`; every network, TLS, `uv`, disk, and lock failure is `reportable=False`, background failures return a structured `{"status": "backoff", "next_retry_at": ...}`, and a successful activation or up-to-date result clears backoff.
- **Canonical Thin-Host MCP Gateway (`mindie_harness.mcp.gateway` / `knowledge_rpc`)**: `ManagedMCPAdapter(DefaultHostAdapter)` unifies `remote`, `tools`, `components`, `knowledge`, and `all` surfaces across all 7 hosts, extracts `_meta` / host-env session identities with a `{host}-conn-<12hex>` connection fallback, and never fails closed. Component commands run as `[python, "-I", "-X", "utf8", "-m", <module>]` (including Windows, avoiding Smart App Control `.exe` blocks); `rebind_native_plugin_if_needed` atomically rebinds the standard `profiler` / `sim` / `coordinator` / `diagnostics` / `debugger` commands under `.update.lock`. `knowledge_rpc` defines the 5 canonical `knowledge_*` schemas, lazy `mindie_knowledge` RPC, and Receipt Honesty (`isError=False` + `receipt_warning` + `receipt_unconfirmed=True` when only the local receipt fails).
- **Sharing Tier CLI and Local-Only Capture (`mindie_harness.sharing` / `installer` / `api`)**: Adds `sharing --status/--enable/--local-only/--disable`, writing `mindie-consent.json`, `mindie-community.json`, and a `mindie.diagnostics.reporting.v1` policy with pure-stdlib atomic writers. `local-only` authorizes local `Stop`/`SessionEnd` transcript capture without community reporting, and the recommended tier is `contribute` when `gh` is authenticated, otherwise `local-only`. Adds `install --host auto|codex|cc|kimi|dsh|agy|wb|oc` host detection, bounded zero-popup `gh api user --jq .login`, zero-Git runtime provisioning, deterministic onboarding JSON, plus `doctor --probe-remote/--cwd/--timeout`, `update --force/--offline/--channel-base-url/--background`, and `mcp --managed` CLI subcommands.
- **Cold `local-only` Stop Gate and Seed Sync (`mindie_harness.bootstrap.seed_main`)**: `render_plugin_bootstrap_template` and `_seed_stop_roots` now accept both `contribute` and `local-only` tiers for local `Stop`/`SessionEnd` capture inside `project_roots`; `dist/mindie-harness-seed.pyz` / `dist/seed-lock.json` (`mindie-harness-seed/1`) were rebuilt and verified with `--check`.
