# mindie-harness 0.1.3：Great Subtraction、零 Git Wheelhouse 底座扩展与 local-only 冷 Stop

[English](harness-0.1.3.en.md)

`mindie-harness v0.1.3` 正式发布，作为 MindIE Agent 全系 7 个原生宿主插件（`codex`、`cc`、`kimi`、`dsh`、`agy`、`wb`、`oc`）共用纯标准库底座（`mindie_harness`）的补丁版本，在不改变 `API_VERSION = 1` 的前提下，收敛诊断入口、原生只读工具分类与原生等待超时边界：

- **`mindie_doctor` 只读快车道与优雅降级（`mindie_harness.mcp.router` / `mindie_harness.api`）**：默认工具目录注册 `mindie_doctor`（`readOnlyHint=True`，可选 `cwd: str` 与 `probe_remote: bool = False`），调用始终进入无锁只读线程池，不占用 `MAX_CONCURRENT_MUTATIONS_PER_SESSION`、不写入 `remote-receipts.sqlite3` 变更行。调度优先惰性调用 `mindie_diagnostics.doctor.run_doctor`，缺失时回退到有界的 `mindie-diagnostics doctor` 子进程；更早的回滚代缺少 `doctor` 时返回结构化 `doctor_unavailable`，绝不击穿 MCP 路由。
- **7 宿主原生读/轮询/控制工具全覆盖**：`READONLY_TOOL_PREFIXES` 新增大小写精确的 `remote_Read`、`remote_Glob`、`remote_Grep`、`remote_TaskOutput`、`remote_TaskList`、`remote_TaskStop`、`remote_ViewImage`、`remote_ReadMediaFile`、`remote_view_image`、`remote_probe`、`remote_read_file`、`remote_find_by_name`、`remote_grep_search`、`remote_list_dir`、`remote_manage_task` 等原生名称；`remote_Write`、`remote_Edit`、`remote_write_file`、`remote_edit_file`、`remote_run_command`、`remote_Bash` 仍严格归类为变更型调用。`remote_auth` 保持出静态前缀表，仅在 `action == "status"` 时走只读快车道，`setup` / `forget` 继续记录变更回执。
- **原生等待超时表与诊断预算（`compute_tool_deadline`）**：`REMOTE_NATIVE_MAX_WAIT_MS` 新增 `remote_Bash` 与 `remote_TaskOutput` 的 `600_000ms` 长轮询上限，并在 `remote` 表面同时识别 `yield_time_ms`、`timeout_ms`、Antigravity `WaitMsBeforeAsync` 与 Claude/WB `timeout`（均为毫秒）。`mindie_doctor` 使用 `10s`（本地）/ `15s`（含 `probe_remote`）内层预算加 cleanup grace，保证外层 `outer >= inner + grace`。
- **版本与 Seed 同步**：`pyproject.toml`、`mindie_harness.__version__`、公开门面、双语 README、发布工作流与 `dist/mindie-harness-seed.pyz` / `dist/seed-lock.json`（`mindie-harness-seed/1`）统一升至 `0.1.3`（`API_VERSION = 1`）。
- **零 Git 预构建 Wheelhouse 更新器（`mindie_harness.runtime.wheelhouse` / `wheelhouse_assets`）**：新增 `discover_channel`、`stage_wheelhouse`、`update_runtime`，从 GitHub Releases 或 `file://`/本地镜像读取 `release-channel.json`、`mindie-wheels-bundle.tar.gz` 与 `SHA256SUMS`，以 `64 KiB` 流式 SHA-256 校验后原子落盘；bundle 缺失时按组件回退到 `<repo>/releases/download/v<version>/*-py3-none-any.whl`，全程零 `git` / `git+https://`。`6h` channel 缓存与 `1h -> 2h -> 4h -> 6h` 有界指数退避写入 `channel-cache.json` / `update-backoff.json`；任何网络、TLS、`uv`、磁盘或锁失败均标记 `reportable=False`，后台失败返回结构化 `{"status": "backoff", "next_retry_at": ...}`，成功激活或已是最新时清除退避。
- **规范薄宿主 MCP 网关（`mindie_harness.mcp.gateway` / `knowledge_rpc`）**：`ManagedMCPAdapter(DefaultHostAdapter)` 统一 7 宿主 `remote`、`tools`、`components`、`knowledge`、`all` 表面、`_meta`/宿主环境会话身份提取与 `{host}-conn-<12hex>` 连接级回退；组件命令以 `[python, "-I", "-X", "utf8", "-m", <module>]` 在 Windows 上规避 Smart App Control，并支持 `rebind_native_plugin_if_needed` 在 `.update.lock` 下原子重绑 `profiler`/`sim`/`coordinator`/`diagnostics`/`debugger` 标准命令；`knowledge_rpc` 提供 5 个规范 `knowledge_*` Schema、惰性 `mindie_knowledge` RPC 与 Receipt Honesty（本地回执失败保持 `isError=False` + `receipt_warning` + `receipt_unconfirmed=True`）。
- **共享分层 CLI 与本地 `local-only`（`mindie_harness.sharing` / `installer` / `api`）**：新增 `sharing --status/--enable/--local-only/--disable`，以纯标准库原子写入 `mindie-consent.json`、`mindie-community.json` 与 `mindie.diagnostics.reporting.v1` 策略；`local-only` 授权本地 `Stop`/`SessionEnd` 转写但不启用社区上报，`gh` 已认证时推荐 `contribute`，否则推荐 `local-only`。新增 `install --host auto|codex|cc|kimi|dsh|agy|wb|oc` 主机探测、有界零弹窗 `gh api user --jq .login` 探测、零 Git 运行时装配与确定性 onboarding JSON，以及 `doctor --probe-remote/--cwd/--timeout`、`update --force/--offline/--channel-base-url/--background` 与 `mcp --managed` 子命令。
- **冷启动 `local-only` Stop 门控与 Seed 同步（`mindie_harness.bootstrap.seed_main`）**：`render_plugin_bootstrap_template` 与 `_seed_stop_roots` 同时接受 `contribute` 与 `local-only` 层级，在 `project_roots` 内授权本地 `Stop`/`SessionEnd` 转写；`dist/mindie-harness-seed.pyz` / `dist/seed-lock.json`（`mindie-harness-seed/1`）已重建并通过 `--check`。
